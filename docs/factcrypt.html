Give an agent the structure. Keep the values with their owner.

FactCrypt protects selected facts in Markdown and source tables. An external model proposes formulas over opaque references. The owner validates the plan, decrypts locally and calculates the result.

What the agent sees

The public document contains random fact references, declared types, units, roles and allowed operations. A table heading remains a heading and a cell remains a cell. The model can propose round(fact("price_id") * fact("quantity_id"), 2) without seeing either value.

The local interpreter uses bounded Decimal arithmetic and checks the entire plan before decryption. Arbitrary Python/JavaScript, file access and network calls are not executed. Derived results remain secret and are not returned to the model automatically.

The application chooses the task

FactCrypt supplies a public protocol contract: fact references, types, units, permitted operations and the response schema. The calling application supplies the user task. The installed Pro library contains no procurement task, sample dataset or task-solving worker.

Pro 3.2.0 includes the generic agent_contract() API and a self-contained private notebook covering profit and margin, weighted mixtures, stock coverage and measurement error through the same library. The deterministic task workers belong to examples and tests; these checks establish protocol and calculation independence, not live-model reasoning.

The older procurement walkthrough below remains a recorded application example. Demo commands moved to examples/factcrypt/ in the private repository.

Encryption begins at the trusted source boundary

A fresh document key encrypts the facts with XChaCha20-Poly1305. The key is wrapped for the owner's Curve25519 public key. The source signs the export. A separately pinned Platform authority can sign permissions while the owner retains its private decryption and result-signing keys.

The E2E recipient is the owner/local resolver. An ordinary encrypted channel ending at the external agent would reveal the values to that agent. If an adapter runs after a remote fetch, that preceding transport remains inside the trusted boundary.

A complete owner workflow in Pro 3.3

The local workbench lets you prepare and inspect a protected document before giving it to an agent. Source values, the vault and owner keys stay on your device. Pro is a paid private package; it is not distributed through public PyPI.

In the Platform, import the local source profile in agent permissions, review and save the column rule, then download the connection settings for the local workbench. The passport displays the rule and permission state. Rule changes are signed and checked before source reading; revocation blocks new acquisitions.

The workbench does not call a model automatically. Its self-test does not test a real source or model. Source versions are owner/source assertions. Arbitrary task text still uses the bounded numeric formula language; it does not enable semantic reasoning about hidden text. Public metadata can support inference and must be reviewed.

What confidentiality does not promise

Unmarked prose, row order, counts, units and other public metadata can reveal context. The disclosure report lists this exposure; it does not prove that a model cannot infer a hidden value. Signatures establish attribution and integrity, not the truth of a source or the business correctness of a formula.

FactCrypt uses authenticated encryption and symbolic local calculation. It does not make ordinary arithmetic work on ciphertext. The source is trusted with its original data; key custody, recipient changes and outward disclosure of aggregates require explicit policy.

Кратко по-русски

Режим задаётся в разрешении «агент → источник» и отображается в паспорте. Источник шифрует значения для владельца; внешняя модель видит структуру и пишет формулы по ссылкам. Локальный исполнитель проверяет формулы, расшифровывает факты и получает точный результат. Ключ расшифровки внешнему агенту не передаётся.
